# План реализации: задачи как центр управления агентами

## Цель

Сделать задачу основной точкой запуска и контроля агентской работы:

- из задачи можно подключить существующий агентский чат или поднять новый;
- агент получает контекст задачи, комментариев, чеклистов, проекта и воркспейса;
- агент может писать комментарии, обновлять чеклисты и двигать статус задачи только в рамках выданных прав;
- мессенджер остается самостоятельным режимом для всех пользователей;
- доступ к воркспейсам и AI выдается только Никитой (`+79679812438`), роль `superadmin`.

## Этап 1. Policy-ядро

1. Добавить общий Python-модуль `agent_policy.py`.
2. Описать роли, capabilities, режимы агентов, категории плагинов.
3. Нормализовать телефон Никиты как `79679812438`.
4. Реализовать `build_user_access`:
   - Никита получает `superadmin` и все рабочие capabilities;
   - обычный пользователь получает только `messenger.use`.
5. Реализовать `build_agent_run_policy`:
   - проверяет `workspaces.use`, `tasks.manage_agent`, `ai.use`;
   - выбирает режим агента по типу задачи;
   - выдает только разрешенные плагины и команды.
6. Реализовать подпись и проверку policy-ticket.

## Этап 2. Защита bridge

1. Добавить secure-mode в `CodeWhaleBridge`.
2. Для workspace/session-команд требовать policy-ticket.
3. Запрещать команды, которых нет в `allowed_commands`.
4. Сохранять совместимость текущих тестов: secure-mode включается параметром.

## Этап 3. Мобильные модели и UI задачи

1. Добавить Dart-модель `AgentAccessPolicy`.
2. Добавить вкладку `Агент` в редактор задачи.
3. На вкладке показывать:
   - режим;
   - разрешенные действия;
   - плагины;
   - подсказку по правам;
   - кнопки `Подключить чат` и `Новый чат`.
4. Реальный запуск: UI получает policy-ticket/context pack, создает CodeWhale session и отправляет стартовый контекст агенту.

## Этап 4. Backend/API

1. Добавить Laravel-сервис прав для профилей.
2. Добавить endpoints:
   - `/me/access`;
   - `/agent/policy`;
   - `/agent/ticket`.
3. Зафиксировать в audit log выдачу доступа к воркспейсам и агентам.
4. Исправить найденные проблемы прав:
   - удаление проектов/групп только владельцем или админом;
   - управление групповыми чатами только участниками с правами;
   - разделить смысл messenger-групп и project-групп.

## Этап 5. Agent-task синхронизация

1. При запуске агента формировать Context Pack из задачи.
2. Ответы агента сохранять в `TaskCollaboration.activity`.
3. Итоги агента писать комментарием.
4. Статус двигать автоматически:
   - запуск агента -> `В работе`;
   - агент просит ревью -> `На проверке`;
   - подтверждено выполнение -> `Выполнено`.

## Проверка готовности

- Python unit tests по policy и bridge проходят.
- Flutter tests по модели и вкладке `Агент` проходят.
- Existing tests по task editor не сломаны.
- Mobile profile содержит админ-панель выдачи и отзыва workspace-доступов для суперадмина.
- Документы ТЗ и план лежат в `docs/superpowers`.
- Изменения закоммичены и запушены.
