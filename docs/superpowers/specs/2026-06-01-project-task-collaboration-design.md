# Project Task Collaboration Design

## Goal

Доработать карточку задачи проектного менеджера в мобильном Flutter-приложении: вместо bottom sheet открывать полноценный экран задачи с вкладками "Настройки" и "Работа", где команда может вести обсуждение, прикреплять фото/файлы, смотреть превью, вести чеклисты и получать структурированный контекст для будущих AI-агентов.

## Scope

- Открытие существующей или новой задачи через полноэкранный route.
- Вкладка "Настройки": название, проект, группа, дата, время, статус, приоритет, ответственные, напоминания, оценка времени.
- Вкладка "Работа": описание задачи, комментарии в стиле чата, вложения с подписью, фотопревью с полноэкранным просмотром, файлы, чеклисты, краткая активность.
- Данные collaboration хранятся структурированно в задаче и синхронизируются вместе с ней.
- Редактирование доступно пользователям, которые уже имеют доступ к задаче через ответственных или группу проекта.

## Data Model

`TaskItem` получает поле `collaboration`:

- `comments`: автор, текст, время, связанные вложения.
- `attachments`: тип `photo` или `file`, имя файла, mime type, base64-данные, подпись, автор и время.
- `checklists`: название, пункты, состояние выполнения, авторы создания/закрытия.
- `activity`: короткая хронология действий для людей и AI-контекста.

`details` остается legacy-полем описания задачи, но в интерфейсе переносится во вкладку "Работа".

## Sync

Локальный SQLite получает колонку `collaboration_json`. Мобильный sync отправляет поле `collaboration` в payload. PHP backend и Laravel backend принимают, сохраняют и возвращают это поле для `tasks` и `family_tasks`. Старые задачи без поля получают пустую структуру.

## UX

- Экран задачи имеет `AppBar` с кнопкой назад и сохранением.
- `TabBar` всегда виден сверху.
- Комментарии выглядят как чат: автор, время, пузырь сообщения, вложения внутри сообщения.
- Composer позволяет выбрать фото или файл, сразу добавить подпись и отправить одним действием.
- Фото показываются маленьким превью и открываются в полноэкранном viewer.
- Чеклист показывает прогресс, добавление пунктов, переключение выполнения.
- На карточке задачи появляются компактные индикаторы комментариев, вложений и прогресса чеклистов.

## Acceptance Criteria

- Нажатие на задачу открывает полноценный экран, а не modal bottom sheet.
- На экране есть две вкладки: "Настройки" и "Работа".
- Описание находится во вкладке "Работа".
- Можно добавить комментарий без вложений.
- Можно добавить фото или файл с подписью.
- Фото показывается как превью и открывается на весь экран.
- Можно создать чеклист, добавить пункт и отметить его выполненным.
- Новые collaboration-данные проходят `TaskItem` JSON, DB row и sync payload.
- Видимость/редактирование остаются привязаны к текущей логике проекта, группы и ответственных.
- Flutter widget/model tests проходят.

## Risks

- Base64-вложения в задаче просты для sync и AI-контекста, но не подходят для очень больших файлов. Позже можно вынести бинарные файлы в отдельное media API, оставив в `collaboration` только metadata и ссылки.
- Одновременное редактирование одной задачи несколькими участниками сейчас конфликтует по версии всей задачи. Для следующего этапа стоит добавить отдельные события collaboration вместо замены всего JSON.
