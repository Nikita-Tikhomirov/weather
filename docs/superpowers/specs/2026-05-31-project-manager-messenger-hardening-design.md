# ТЗ: проектный менеджер и мессенджер

Дата: 2026-05-31

## Цель

Довести мобильные разделы "Проекты" и "Мессенджер" до рабочего состояния перед связкой с рабочими пространствами и чатами с ИИ.

## Обнаруженный техдолг и баги

1. Проектный менеджер хранит выбранный проект только в памяти.
   - После перезапуска приложение возвращается без выбранного проекта.
   - Требуемое поведение: открывается последний валидный проект, который пользователь выбирал; для рабочих пространств CodeWhale восстанавливается последний workspace и последняя открытая сессия, если она еще существует.

2. Проектный режим не должен показывать и создавать личные дела.
   - Текущая доменная логика уже требует `projectId` для новой задачи и фильтрует задачи по текущему проекту.
   - Требуется закрепить это поведение тестами и не возвращать fallback к личным задачам, когда есть хотя бы один доступный проект.

3. Чат визуально "прыгает" при открытии и обновлении.
   - `ChatMessagesList` несколько раз анимированно доскролливает вниз после открытия.
   - Требуемое поведение: при входе в чат список один раз ставится в нижнюю позицию без видимой анимации; при подгрузке старых сообщений позиция сохраняется; при новых сообщениях автоскролл включается только если пользователь уже был у нижнего края или сообщение отправил текущий пользователь.

4. Видео в фоне может продолжать звучать после открытия чата.
   - `VideoThumbnail` запускает `play()` для получения кадра, а контроллер присваивается в состояние только после задержки.
   - Если виджет уничтожен до присваивания, контроллер не останавливается и не освобождается.
   - Требуемое поведение: миниатюры видео не запускают слышимое воспроизведение и всегда останавливают/освобождают контроллер.

5. Аудио- и видеозвонки неполные.
   - Экран звонка показывает только удаленный поток или заглушку.
   - Нет локального self-preview с вебки.
   - Нет отдельного управления маршрутом "гарнитура/Bluetooth".
   - Требуемое поведение: для видеозвонка локальный поток виден в правом нижнем углу, его можно перетаскивать, он не перекрывает нижнюю панель кнопок; есть кнопки микрофона, завершения, динамика и гарнитуры/Bluetooth.

6. Семейные группы и групповые чаты рассинхронизированы.
   - Создание/редактирование `family_groups` не создает и не обновляет `chat_conversations`.
   - Требуемое поведение: для каждой группы автоматически создается стабильный групповой чат; владелец и участники группы являются участниками чата; при добавлении участника в группу он появляется в чате.

## Приоритеты реализации

P0:
- остановить фоновое воспроизведение видео-превью;
- стабилизировать скролл чата;
- добавить self-preview и базовый маршрут гарнитуры/Bluetooth в звонках;
- синхронизировать семейные группы с групповыми чатами.

P1:
- сохранять и восстанавливать последний выбранный ToDo-проект;
- сохранять и восстанавливать последний workspace/session в менеджере рабочих пространств;
- закрепить проектный режим без личных задач тестами.

P2:
- дальнейшая полировка звонков: список конкретных audio output устройств, индикатор сетевого состояния, повторное подключение после краткого обрыва.

## Архитектура изменений

### Flutter

- `TaskStore` получает зависимость `ProjectSelectionStorage`.
- По `initialize()` стор восстанавливает последний выбранный проект для текущего профиля после загрузки проектов.
- `setCurrentProject()` сохраняет выбор.
- Если сохраненный проект больше не доступен, стор выбирает первый доступный проект и перезаписывает сохраненное значение.

- `CodeWhaleWorkspacesPage` сохраняет последний открытый workspace и session.
- После получения списка workspaces страница восстанавливает последний workspace.
- После получения списка sessions для восстановленного workspace страница открывает последнюю session, если она еще существует.

- `ChatMessagesList` получает чистую политику автоскролла.
- Начальная прокрутка выполняется через `jumpTo`, а не через серию `animateTo`.
- При изменении списка сообщений решение об автоскролле принимается по состоянию до обновления.

- `VideoThumbnail` перестает запускать слышимое видео.
- Контроллер присваивается сразу после создания, переводится в mute, кадр подготавливается без `play()` где возможно, а при отмене асинхронной инициализации всегда освобождается.

- `CallService` публикует локальный поток через `onLocalStream`.
- `CallScreen` инициализирует локальный `RTCVideoRenderer`, показывает draggable preview и добавляет кнопку предпочтения гарнитуры/Bluetooth через `Helper.setSpeakerphoneOnButPreferBluetooth()`.

### Backend

- `ChatRepository` получает метод синхронизации family group -> group chat.
- Ключ чата стабильный: `grp:family:<group_id>`.
- `ProjectGroupController::createGroup()` и `updateGroup()` вызывают синхронизацию после записи группы.

## Критерии приемки

- После выбора проекта и перезапуска стор восстанавливает этот проект.
- Если сохраненный проект удален или недоступен, стор выбирает первый доступный проект, чтобы не показывать личные задачи в проектном режиме.
- В менеджере рабочих пространств при повторном входе открывается последний workspace/session, если они еще доступны.
- Новая задача без проекта не сохраняется.
- Открытие чата не запускает серию видимых автоскроллов.
- Подгрузка старых сообщений не уводит пользователя вниз.
- Видео-превью не оставляет активный проигрыватель после ухода со страницы.
- В видеозвонке есть локальное окно камеры справа снизу; его можно перетащить в безопасную область.
- Кнопка гарнитуры/Bluetooth переводит аудио в режим "динамик выключен, Bluetooth предпочтителен".
- Создание семейной группы создает групповой чат.
- Обновление состава семейной группы обновляет участников группового чата.
